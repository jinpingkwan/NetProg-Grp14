01 Overview

NetAuto is a command-line automation toolkit that configures network devices and reports on Linux host status from a single tool. It satisfies the assignment's requirement to develop an automation solution using Docker, Ansible, NETCONF, or a combination of these technologies by combining all three: Ansible performs the actual configuration and data collection, Docker/Containerlab hosts a reproducible lab of simulated devices and servers, and a Typer-based CLI (netauto) gives the team and the grader a clean, documented entry point instead of raw ansible-playbook invocations.

02 Objectives

The toolkit will:

  1. Configure an IP address on a target network device
  2. Create a user account on a target network device
  3. Set a banner message on a target network device
  4. Set an interface description on a target network device
  5. Add a static route on a target network device
  6. Retrieve and display general device information
  7. Automatically collect and display Linux system information: hostname, current date/time, CPU info, memory usage, disk usage, logged-in users, and the top 5 processes by CPU usage

All work will be tracked through a shared GitHub repository with commits from every member, in line with the assignment's collaboration requirements.

04 System architecture

GitHub repo (source code) | v Typer CLI ("netauto") | v Ansible (playbooks & roles) | +----> Network devices (Docker/Containerlab) | IP, user, banner, interface, static route, device info | +----> Linux hosts (Docker/Containerlab) hostname, date/time, CPU, memory, disk, users, top processes

The CLI never talks to devices directly — every netauto subcommand resolves to an Ansible playbook run against a named host or group defined in a shared inventory file. This keeps device-specific connection details (SSH vs. NETCONF, credentials, OS type) out of the CLI code entirely.

05 Functional requirements

5.1 Device configuration tasks (network devices)

Configure IP address

$ netauto configure ip router1 --ip 192.168.10.1 --mask 255.255.255.0

Create user account

$ netauto configure user router1 --username admin

Set banner message

$ netauto configure banner router1 --message "Authorized access only"

Set interface description

$ netauto configure interface router1 --iface Gi0/1 --desc "Uplink to core"

Add static route

$ netauto configure route router1 --dest 10.0.0.0/24 --via 192.168.10.254

Retrieve device info

$ netauto info device router1

06 Repository and collaboration plan

Branching: each member works on a feature branch (e.g. feature/cli-commands, feature/ansible-roles) and merges via pull request, so individual contribution is visible in commit history.

Folder structure

netauto/ ├── cli/ # Typer CLI source ├── playbooks/ # Ansible playbooks, one per task ├── roles/ # Reusable Ansible roles ├── inventory/ # Host/group definitions ├── lab/ # Docker / Containerlab topology files ├── docs/ # README, usage guide └── reflections/ # Personal reflection reports

Commit convention: short, descriptive messages (e.g. add: static route playbook, fix: ip validation in CLI) so the history reads as a clear record of who did what.
